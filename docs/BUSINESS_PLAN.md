## 一、项目概述

### 1.1 一句话定位

**StarClaw 是开源 AI Agent 编排平台，让每个人和每个企业都能拥有自己的 AI 智能体军团。**

### 1.2 核心理念

灵感来自《星际争霸》虫族——每一个部署的 StarClaw 实例就是一只"小龙虾（Claw）"，它们由"领主（Overlord）"管理，所有领主最终汇聚到"虫后（Queen）"的中央管控之下。

```
                         👑 Queen（虫后）
                    starclaw.net — 中央大脑
                         │
      ┌──────────┬───────┼───────┬──────────┐
      │          │       │       │          │
 👁️ Overlord 🧠 Cerebrate ⛽ Synapse  🐛 Larva
  企业管控层   合伙人生态    算力网关    用户客户端
      │          │           │          │
      └────┬─────┴───────────┘          │
           │                            │
      🦞🦞🦞 Claw（小龙虾）               │
       AI Agent 执行单元 ◄──────────────┘
```

### 2.2 行业痛点

| 痛点 | 现状 | StarClaw 方案 |
|------|------|-------------|
| **AI 碎片化** | 企业需对接 OpenAI/Claude/Qwen 等多个 API | Synapse 统一网关，50+ 模型一键接入 |
| **缺乏编排能力** | 单一对话无法完成复杂业务流程 | 可视化工作流 + Multi-Agent 协作 |
| **数据安全顾虑** | 企业不愿将数据传给第三方 SaaS | 开源自部署 + 本地模型支持（Ollama） |
| **成本不可控** | AI API 按量计费，企业无法预算 | 预算告警 + 用量统计 + 团队配额管理 |
| **Agent 孤岛** | 各团队的 AI 工具各自为政 | 虫群网络，统一管控，数据互通 |

| 编程 Agent | 自主编码、文件操作、13 种语言代码沙箱 |

| P2P 加密通信 | Ed25519 身份体系，Gossip 协议 |

### 3.3 Overlord 企业管控（付费产品）

面向企业 IT 管理员，提供完整的 AI 治理能力：

- **节点编排**：管理 N 个 Claw 节点，统一下发配置和更新
- **多租户 RBAC**：4 级角色（superadmin/admin/operator/viewer）
- **SSO 集成**：OAuth2/OIDC + LDAP，企业微信/飞书一键登录
- **Molt 更新**：版本审批 → 滚动更新 → 自动熔断
- **预算告警**：团队/部门 AI 消费预算管控
- **审计日志**：完整操作追溯
- **Team Agent**：19 种官方团队智能体模板（开发/营销/客服/数据/法务/财务/量化/电商…）

**60+ API 端点，17 张数据表，2 套前端控制台。**

### 3.4 Hive 云托管（IaaS 产品）

一键创建属于自己的 Claw 节点，10 秒可用。以下为**单个节点**的配置：

| 套餐 | 价格 | CPU | 内存 | 存储 | 数据库 | 亮点 | 适合 |
|------|:----:|:---:|:----:|:----:|------|------|------|
| 🔥 **Spark** | 永久免费 | 0.25核 | 256MB | 1GB | SQLite | 2个团队智能体、3秒极速部署 | 个人体验 |
| ⚡ **Pulse** | ¥50/月 | 1核 | 1GB | 10GB | MySQL+Redis | 10个团队智能体、Web UI 管理面板、每日自动备份 | 小团队 |
| 🚀 **Surge** | ¥200/月 | 2核 | 4GB | 40GB | 独立云服务器 | 无限团队智能体、自定义域名、5Mbps带宽、高级监控 | 中型企业 |
| 👑 **Storm** | ¥800/月 | 4核 | 8GB | 100GB | 独立高配服务器 | SSO企业登录、10Mbps带宽、SLA 99.9%、专属技术支持 | 大型企业 |

升级时数据无缝迁移，节点 ID 不变，团队智能体不中断。

### 4.2 利润分配机制

```
平台交易利润
    │
    ├─ 城市合伙人佣金      30%（如有）
    ├─ 团队合伙人佣金      30%（如有）
    ├─ 平台留存            30%
    └─ 投资人利润池（星钻） 10%（始终固定）
```

**投资人始终获得利润的 10%，不受合伙人分配影响。**

```

  │                        │                │

  └─ 企业订阅               └─ 工具调用        └─ 星钻池 10%
```

## 八、融资方案 — 星钻 (Star Diamond)

### 8.1 融资工具

星钻是 StarClaw 平台的**利润池收益权凭证**，持有星钻的投资人按份额享受平台交易利润的 10% 分配。

| 属性 | 值 |
|------|-----|
| 名称 | 星钻 (Star Diamond) |
| 总量 | **1 亿份**（固定，永不增发） |
| 法律定性 | **收益权凭证**（非股权、非代币、非基金份额） |
| 定价机制 | `价格 = max(NAV 净值, 轮次地板价)` |
| 分红来源 | 平台交易利润的 10%，按月分配 |
| 投资协议 | 《收益权转让协议》，1/3/5 年期 |

### 8.2 五轮融资路线

| 轮次 | 代号 | 地板价 | 配额 | 最大募资 | 倍数 | 状态 |
|------|------|:------:|:----:|:-------:|:----:|:----:|

**5 轮合计最大募资: ¥39.75 亿** | 平台储备 50% = 5,000 万份（未来生态激励）

### 8.3 双驱动定价机制

```
星钻价格 = max(NAV 净值价, 轮次地板价)

  NAV = (累计投资 + 累计利润入池 - 已分红总额) / 已发行星钻数

  → 利润积累推高 NAV → 价格上涨（业务驱动）
  → 轮次推进抬高地板 → 价格上涨（里程碑驱动）
  → 两者互为安全网，价格在正常经营下持续上行
```

### 8.4 投资人回报演示

```
场景：孢子期投入 ¥5 万，购买 10 万份星钻 @ ¥0.50/份

① 分红收益（假设平台月利润 ¥50 万，投资池获 10% = ¥5 万/月）
   投资人持有 10 万/1000 万 = 1% 份额
   月分红 = ¥5 万 × 1% = ¥500
   年分红 = ¥6,000 → 年化 12%（仅分红，不含增值）

② 资本增值（假设进入虫兵期，价格达 ¥12.50/份）
   10 万份 × ¥12.50 = ¥125 万
   投入 ¥5 万 → 市值 ¥125 万 = 25 倍回报

③ 综合回报 = 分红收益 + 资本增值
```

> 以上仅为演示性示例，实际收益取决于平台业务发展，不构成收益承诺。
