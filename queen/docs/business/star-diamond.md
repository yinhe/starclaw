# 星钻 (Star Diamond) — 收益权凭证系统设计文档

> 动态定价 · 双驱动增长 · 合规收益权模式

---

## 一、概述

星钻是 StarClaw 平台的**利润池收益权凭证**，持有星钻的投资人按份额享受平台交易利润的 10% 分配。

**核心特征：**

| 属性 | 值 |
|------|-----|
| 名称 | 星钻 (Star Diamond) |
| 总量 | **1 亿份**（固定，永不增发） |
| 初始价格 | ¥0.20/份（种子轮地板价） |
| 定价机制 | `price = max(NAV净值价, 轮次地板价)` |
| 法律定性 | **收益权凭证**（非股权、非代币、非基金份额） |

## 三、双驱动定价机制

星钻价格由两个因素中的**较大者**决定：

```
星钻价格 = max(NAV净值价, 轮次地板价)

其中:
  NAV = (TotalRaised + TotalDeposited - TotalDistributed) / TotalShares
      = (投资人累计充值 + 利润池累计入账 - 已分红总额) / 已发行星钻数

  轮次地板价 = 当前融资轮次的最低价格
```

### 3.1 NAV 净值驱动（利润推高）

NAV 随平台业务增长而自然上涨：

- Claw 节点每笔 AI 交易产生利润（upstream cost × 10% markup）
- 利润的 **10%** 自动注入投资人池（`TotalDeposited` 增加）
- 投资人充值也增加池子资产（`TotalRaised` 增加）
- NAV = 总资产 / 已发行星钻 → **业务越好，NAV 越高**

### 3.2 轮次地板价驱动（里程碑推高）

每进一个融资轮次，地板价 5× 跳涨：

| 轮次 | 代号 | 地板价 | 倍数 |
|------|------|:------:|:----:|
| 孢子轮 | spore | ¥0.20 | 1× |
| 幼虫轮 | larva | ¥1.00 | 5× |
| 虫兵轮 | zergling | ¥5.00 | 25× |
| 领主轮 | overlord | ¥25.00 | 125× |
| 虫后轮 | queen | ¥125.00 | 625× |

### 3.3 演进示例

```
孢子轮初期 (Spore):
  NAV = ¥0 (无利润), 地板 = ¥0.20
  → 价格 = ¥0.20 【地板价驱动】

孢子轮末期 (利润积累):
  NAV = ¥0.60, 地板 = ¥0.20
  → 价格 = ¥0.60 【NAV驱动 ✨ 利润推高了价格】

幼虫轮开启 (Larva):
  NAV = ¥0.60, 地板 = ¥1.00
  → 价格 = ¥1.00 【地板价驱动 ✨ 轮次推高了价格】

幼虫轮末期 (业务增长):
  NAV = ¥3.50, 地板 = ¥1.00
  → 价格 = ¥3.50 【NAV驱动 ✨ 利润再次推高】

虫兵轮开启 (Zergling):
  NAV = ¥3.50, 地板 = ¥5.00
  → 价格 = ¥5.00 【地板价驱动】

领主轮开启 (Overlord):
  NAV = ¥18.00, 地板 = ¥25.00
  → 价格 = ¥25.00 【地板价驱动】

虫后轮中后期 (Queen):
  NAV = ¥200.00, 地板 = ¥125.00
  → 价格 = ¥200.00 【NAV驱动】

孢子轮 ¥0.20 买入 → 虫后轮时 ¥200.00 = 1000倍真实回报
```

**设计哲学：** 价格永远只涨不跌（在正常经营下）。利润积累推高 NAV，新轮次推高地板价，两者互为安全网。即使某段时间利润放缓（NAV 增长慢），轮次地板价也确保价格不回落。

## 五、投资人操作流程

### 5.1 完整生命周期

```
注册 → 签署协议 → 充值购买星钻 → 激活分润 → 每月分红 → 到期退出/续约

POST /v1/investor/register          ← 自助注册
POST /v1/investor/agree             ← 签署《收益权转让协议》(1/3/5年)
POST /v1/investor/recharge          ← 充值购买星钻 (¥1万起/次)
        ↓ 累计 ≥ ¥10万
    分润自动激活
        ↓ 每月
POST /admin/investor/distribute     ← 管理员发起分红
GET  /v1/investor/earnings          ← 查看每日收益
GET  /v1/investor/me                ← 查看持仓/市值/分红记录
```

### 5.2 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 单次最低充值 | ¥10,000 (1万) | 中国支付限额友好 |
| 激活门槛 | ¥100,000 (10万) | 累计充值达标后开始享受分润 |
| 协议期限 | 1 / 3 / 5 年 | 签署后方可充值 |
| 分红周期 | 月度 | 按持有份额比例分配池子余额 |
| 星钻价格 | 动态 | max(NAV, 轮次地板价) |

### 5.3 购买计算示例

```
场景: 天使轮, 当前NAV = ¥2.00, 地板价 = ¥1.00
  → 实际价格 = max(2.00, 1.00) = ¥2.00/份

投资人充值 ¥100,000 (10万):
  → 购买星钻 = 100,000 / 2.00 = 50,000 份 (5万星钻)
  → 如果总发行 1000万份, 占比 = 5万/1000万 = 0.5%
  → 每月可获: 投资人池月入 × 0.5%
```

## 六、融资轮次管理

### 6.1 轮次配置

| 轮次 | 代号 | 地板价 | 配额 | 最大募资 | 状态流转 |
|------|------|:------:|:----:|:-------:|---------|
| 孢子轮 | spore | ¥0.20 | 1000万份 | ¥200万 | upcoming → open → sold_out |
| 幼虫轮 | larva | ¥1.00 | 1000万份 | ¥1000万 | upcoming → open → sold_out |
| 虫兵轮 | zergling | ¥5.00 | 1000万份 | ¥5000万 | upcoming → open → sold_out |
| 领主轮 | overlord | ¥25.00 | 1000万份 | ¥2.5亿 | upcoming → open → sold_out |
| 虫后轮 | queen | ¥125.00 | 1000万份 | ¥12.5亿 | upcoming → open → sold_out |

> 注: 最大募资 = 配额 × 地板价。如果 NAV 推高了价格，实际募资会更多。

### 6.2 自动推进机制

```
孢子轮 (open)
  ↓ SharesSold >= 1000万 (售罄)
  ↓ 自动: 孢子轮→sold_out, 幼虫轮→open, 价格→max(NAV, ¥1.00)
幼虫轮 (open)
  ↓ 售罄
  ↓ 自动: 幼虫轮→sold_out, 虫兵轮→open, 价格→max(NAV, ¥5.00)
虫兵轮 (open)
  ↓ 售罄
  ↓ 自动: 虫兵轮→sold_out, 领主轮→open, 价格→max(NAV, ¥25.00)
领主轮 (open)
  ↓ 售罄
  ↓ 自动: 领主轮→sold_out, 虫后轮→open, 价格→max(NAV, ¥125.00)
虫后轮 (open)
  ↓ 售罄
  ↓ 自动: 虫后轮→sold_out, CurrentRound→"closed"
```

轮次在投资人充值时自动推进（同一事务内，零停机）。管理员也可随时手动开启任意轮次：

```
POST /admin/investor/round/open
Body: { "round": "zergling" }
```

### 6.3 轮次顺序

```
spore → larva → zergling → overlord → queen → closed

model.NextRound("spore")    → "larva"
model.NextRound("larva")    → "zergling"
model.NextRound("zergling") → "overlord"
model.NextRound("overlord") → "queen"
model.NextRound("queen")    → ""  (no more rounds)
```

## 七、分红机制

### 7.1 分红流程

```
1. 利润持续注入池子 (自动, 每笔交易的10%)
     ↓
2. 管理员发起月度分红
   POST /admin/investor/distribute { "period": "2026-03" }
     ↓
3. 系统计算每位投资人的份额比例
   ratio = investor.Shares / pool.TotalShares
     ↓
4. 按比例分配 PoolBalance
   amount = PoolBalance × ratio
     ↓
5. 创建 InvestorDividend 记录, 更新投资人 TotalDividends
     ↓
6. PoolBalance 扣减, TotalDistributed 增加
```

### 7.2 分红计算示例

```
池子月入: ¥50,000
总发行: 2000万 星钻
投资人持有: 100万 星钻

  ratio = 100万 / 2000万 = 5%
  本月分红 = ¥50,000 × 5% = ¥2,500

年化: ¥2,500 × 12 = ¥30,000
投资人当初花了 ¥100,000 买入, 年化收益率 = 30%
```

> 注意: 这只是分红收益。星钻本身还在增值（NAV上涨），持有人还享有资本增值。

## 十、法律合规 — 路径 C 收益权模式

### 10.1 法律定性

```
星钻 ≠ 证券      → 不需要证监会审批
星钻 ≠ 虚拟货币  → 不违反 ICO 禁令
星钻 ≠ 基金份额  → 不需要中基协备案
星钻 = 收益权凭证 → 合同法框架下的民事协议
```

### 10.2 合规要点

| 要求 | 措施 |
|------|------|
| **不承诺固定收益** | 协议明确"按利润池实际收益分配，不保本不保息" |
| **不公开募集** | 不在公众渠道打广告，仅对特定对象（熟人/转介绍） |
| **投资人数量** | 控制在 **200 人以内**（避免被认定为公开募集） |
| **资金管理** | 投资人资金专项管理，分红来自真实利润 |
| **信息披露** | 定期出具收益报告，投资人可随时查询持仓和收益 |
| **协议签署** | 投资人必须签署《收益权转让协议》，选择 1/3/5 年期限 |
| **退出机制** | 到期按 NAV 结算退出，公司有优先回购权 |

### 10.3 三条红线（绝不能碰）

| 红线 | 说明 |
|------|------|
| 🔴 **不承诺固定收益** | "预期年化 XX%" 是非法集资标志 |
| 🔴 **不公开募集** | 不在公众号/抖音/网站打广告募资 |
| 🔴 **不搞资金池拆东补西** | 分红必须来自真实利润 |

### 10.4 前端展示规范

- ✅ 使用"星钻""收益权凭证""利润分配"
- ❌ 避免"代币""挖矿""区块链""ICO""股份""基金"
- ❌ 不显示"预期年化收益率""保本""保息"

### 10.5 升级路径

```
阶段 1（现在 → A轮前）: 收益权转让模式
  • 成本：律师审协议 ¥5000-2万
  • 投资人 < 50 人
  • 募资规模: ¥1000万

阶段 2（A轮后，投资人 > 50 人）: 有限合伙基金
  • 设立星爪投资合伙企业（有限合伙）
  • 基金备案（中基协）
  • 星钻 → 基金份额（1:1 映射）
  • 成本：¥30-50万

阶段 3（IPO 前）: 转为正式股权
  • 按当时 NAV 折算股权比例
  • 投资人变成正式股东
  • 上市后股票流通 = 真正退出
```
