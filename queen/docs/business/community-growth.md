## 二、GitHub 仓库优化

### 2.1 README 黄金结构

```
# StarClaw 🦂

一句话介绍 + 截图/GIF（3 秒抓住注意力）

## ✨ Features（功能亮点，用图标+短句）
## 🚀 Quick Start（3 步以内跑起来）
## 📦 Installation（详细安装）
## 🏗️ Architecture（一张架构图）
## 🤝 Contributing（贡献指南链接）
## 📄 License（开源许可）
## ⭐ Star History（Star 增长图表）
```

**关键原则：**
- 首屏必须有**产品截图或 GIF 动图**（文字墙没人看）
- Quick Start 必须 **≤3 步**（`git clone` → `docker compose up` → 打开浏览器）
- Badge 行：Stars / License / Docker Pulls / Contributors / Discord

### 2.2 仓库必备文件

| 文件 | 作用 | 状态 |
|------|------|:----:|
| `README.md` | 项目首页，决定 Star 转化率 | [待优化] |
| `CONTRIBUTING.md` | 贡献指南，降低参与门槛 | [待写] |
| `CODE_OF_CONDUCT.md` | 行为准则 | [待写] |
| `CHANGELOG.md` | 变更日志，展示项目活跃度 | [待写] |
| `.github/ISSUE_TEMPLATE/` | Issue 模板（Bug / Feature / Question） | [待写] |
| `.github/PULL_REQUEST_TEMPLATE.md` | PR 模板 | [待写] |
| `LICENSE` | Apache 2.0 / MIT | [确认] |
| `docs/` | 文档站（Docusaurus / VitePress） | [待建] |

### 2.3 Release 策略

| 频率 | 类型 | 内容 |
|------|------|------|
| 每 2 周 | Patch | Bug 修复、小改进 |
| 每月 | Minor | 新功能、API 变更 |
| 每季度 | Major | 重大功能、架构变更 |

> 每次 Release 都写详细 Release Notes，包含：新功能截图 + 改进列表 + 升级指南。
> Release Notes 是免费的营销内容 — 会被 GitHub Trending 和 RSS 聚合器抓取。

## 三、增长渠道

### 3.1 首发冲榜（M1-M2）

| 平台 | 方法 | 预期效果 |
|------|------|---------|
| **Hacker News** | Show HN 帖子，标题格式 "Show HN: StarClaw – Open-source enterprise AI platform with team isolation and audit" | 首页 → 500-2000 Stars |
| **Product Hunt** | 完整 Launch（Logo + 截图 + 视频 + Maker Comment） | Top 5 → 300-800 Stars |
| **Reddit** | r/selfhosted, r/opensource, r/artificial | 100-300 Stars |
| **V2EX** | 发在 /t/share 板块 | 50-200 Stars |
| **少数派 / 即刻** | 产品推荐 + 创始人故事 | 品牌认知 |

**冲榜 Checklist：**
- [ ] README 有产品截图/GIF
- [ ] Docker 一键启动可用
- [ ] Demo 站可在线体验
- [ ] 创始人账号提前养号（HN karma ≥ 50）

## 四、社区运营

### 4.1 社区阵地

| 平台 | 用途 | 语言 | 优先级 |
|------|------|:----:|:------:|
| **GitHub Discussions** | 功能讨论、Q&A | 英/中 | ⭐⭐⭐ |
| **Discord** | 实时交流、社区氛围 | 英文 | ⭐⭐⭐ |
| **微信群** | 中文用户实时交流 | 中文 | ⭐⭐⭐ |
| **Twitter/X** | 品牌传播、行业影响力 | 英文 | ⭐⭐ |
| **公众号** | 深度内容、用户触达 | 中文 | ⭐⭐ |

### 4.2 Issue / PR 响应标准

| 类型 | 首次响应 | 解决时间 | 说明 |
|------|:-------:|:-------:|------|
| Bug Report | 24 小时 | 3-7 天 | 严重 Bug 优先 |
| Feature Request | 48 小时 | 排入 Roadmap | 打标签，社区投票 |
| Question | 24 小时 | 当天 | 简单问题直接回复 |
| Pull Request | 48 小时 | 1-2 周 Review | 感谢 + 详细 Review |

> **铁律：每个 Issue/PR 都要回复。** 不回复 = 社区信心崩塌。

### 4.3 贡献者激励

| 贡献级别 | 条件 | 激励 |
|---------|------|------|
| 🌟 **首次贡献者** | 第 1 个合并的 PR | README 贡献者列表 + 社区感谢 |
| ⭐ **活跃贡献者** | ≥5 个合并的 PR | 贡献者 T 恤 + Discord 角色 |
| 🏆 **核心贡献者** | ≥20 个 PR 或维护子模块 | 写入 MAINTAINERS + 推荐信 + 实物礼品 |
| 💎 **社区大使** | 持续布道 + 组织活动 | 受邀参加内部决策 + 优先体验新功能 |

**Good First Issues：**
- 持续维护 10-20 个 `good first issue` 标签的 Issue
- 难度适中（文档改进、UI 小调整、简单 Bug 修复）
- 每个 Issue 写清楚背景、预期行为、实现提示

## 五、社区到商业的转化

```
GitHub Star → 试用部署 → 社区提问 → 企业需求识别 → 销售跟进

转化漏斗：
  10,000 Stars
    → 2,000 实际部署（20%）
      → 200 社区活跃用户（10%）
        → 40 企业用户识别（20%）
          → 10 付费客户（25%）
```

### 识别企业用户信号

| 信号 | 动作 |
|------|------|
| Issue 中提到"公司"、"团队"、"部署" | 标记为潜在企业用户，私信了解 |
| 问 SSO / LDAP / 审计相关问题 | 企业需求明确，引导到销售 |
| Star 来自企业邮箱（@company.com） | 记录到 CRM |
| 大量节点部署（社区版 5 节点以上问题） | 明确有升级需求 |
