# StarClaw 客户交付流程（SOP）

> 内部文件 — 从签约到上线的标准化流程

---

## 一、交付全景

```
签约 → 启动会 → 环境准备 → 部署 → 配置 → 培训 → 验收 → 上线 → 首月回访
 D0     D1       D2-D3     D3-D5   D5-D7   D8-D9   D10    D11    D30

SaaS 客户：D0 → D3（3 天交付）
私有云客户：D0 → D7（1 周交付）
本地部署客户：D0 → D14（2 周交付）
白牌客户：D0 → D21（3 周交付）
```

---

## 二、角色分工

| 角色 | 谁 | 职责 |
|------|-----|------|
| **销售负责人** | 核心合伙人 / 城市合伙人 | 客户关系维护、商务协调、验收确认 |
| **技术交付** | 核心合伙人（技术方向）/ 平台运维 | 部署、配置、联调、技术培训 |
| **客户对接人** | 客户 IT 主管 / 管理员 | 提供环境、确认需求、内部协调 |
| **项目经理** | 核心合伙人（默认销售负责人兼任） | 进度跟踪、风险管理 |

## 三、标准交付流程

### Phase 1：启动（D0-D1）

**D0 签约当天：**

- [ ] 合同签署完成（电子签）
- [ ] 首期款到账确认
- [ ] 在 Partner Hub CRM 创建客户记录，状态改为「交付中」
- [ ] 分配技术交付人员

**D1 启动会（30 分钟，远程）：**

参会人：销售负责人 + 技术交付 + 客户对接人

| 议程 | 时间 | 内容 |
|------|------|------|
| 介绍 | 5 分钟 | 双方团队介绍、交付流程说明 |
| 需求确认 | 10 分钟 | 团队数量、节点数、模型选择、SSO 需求 |
| 环境确认 | 10 分钟 | 部署方式（SaaS/私有云/本地）、服务器要求 |
| 排期 | 5 分钟 | 确认里程碑日期、下次沟通时间 |

**启动会输出物：**
- [ ] 《交付需求确认表》（模板见附录）
- [ ] 交付排期表（共享给客户）

### Phase 2：环境准备（D2-D3）

**SaaS 客户：**
- [ ] 创建租户实例
- [ ] 配置域名（如客户要自定义域名）
- [ ] 开通管理员账号

**私有云 / 本地部署客户：**
- [ ] 客户提供服务器信息（IP、SSH、配置）
- [ ] 确认服务器满足最低要求：

| 套餐 | CPU | 内存 | 磁盘 | 带宽 |
|------|:---:|:----:|:----:|:----:|
| Starter (≤20 节点) | 2 核 | 4 GB | 50 GB | 5 Mbps |
| Pro (≤100 节点) | 4 核 | 8 GB | 100 GB | 10 Mbps |
| Enterprise (≤500 节点) | 8 核 | 16 GB | 200 GB | 20 Mbps |

- [ ] 确认网络环境（防火墙、端口、代理、模型 API 可达性）

### Phase 3：部署（D3-D5）

**SaaS 部署（30 分钟）：**
```
1. 创建租户 → 2. 配置域名 → 3. 开通管理员 → 完成
```

**Docker 部署（1-2 小时）：**
```
1. SSH 登录客户服务器
2. docker compose up -d（一键启动）
3. 确认服务健康（API + Web + Console 三件套）
4. 配置 HTTPS（Let's Encrypt / 客户证书）
5. 冒烟测试（登录 + 对话 + 创建团队）
```

**K8s 部署（半天）：**
```
1. 确认 K8s 集群信息
2. 应用 Helm Chart
3. 配置 Ingress + TLS
4. 确认 Pod 健康
5. 冒烟测试
```

**部署完成检查清单：**
- [ ] 管理控制台可访问
- [ ] 员工 AI 工作台可访问
- [ ] 至少一个 AI 模型可正常对话
- [ ] 管理员可创建团队和用户

### Phase 4：配置（D5-D7）

| 配置项 | 操作 | 负责人 |
|--------|------|--------|
| 团队创建 | 按客户组织架构创建团队 | 技术交付 |
| 模型配置 | 为每个团队分配可用模型 | 技术交付 + 客户 |
| SSO 对接 | 对接 LDAP / OAuth / 飞书 / 钉钉 | 技术交付 |
| 配额设置 | 每团队月度 Token 限额 | 客户 IT 管理员 |
| 知识库 | 帮客户上传 1-2 个示例知识库 | 技术交付 |
| Agent 模板 | 配置 2-3 个行业通用 Agent | 技术交付 |
| 品牌配置 | （白牌客户）Logo/色调/域名 | 技术交付 |

### Phase 5：培训（D8-D9）

**培训 1：管理员培训（1 小时，远程）**

| 内容 | 时间 |
|------|------|
| 控制台总览 | 10 分钟 |
| 团队/用户管理 | 15 分钟 |
| 模型配置与路由 | 10 分钟 |
| 用量查看与预算设置 | 10 分钟 |
| 审计日志 | 5 分钟 |
| Q&A | 10 分钟 |

**培训 2：员工使用培训（30 分钟，远程，可录屏）**

| 内容 | 时间 |
|------|------|
| 登录与基本对话 | 5 分钟 |
| 切换模型 | 5 分钟 |
| 使用知识库 | 10 分钟 |
| 使用 Agent 模板 | 5 分钟 |
| Q&A | 5 分钟 |

**培训输出物：**
- [ ] 管理员操作手册（PDF）
- [ ] 员工快速入门指南（1 页 PDF）
- [ ] 培训录屏（客户内部分享）

### Phase 6：验收（D10）

**验收检查清单：**

| 序号 | 验收项 | 标准 | 结果 |
|:----:|--------|------|:----:|
| 1 | 管理控制台可正常访问 | 管理员可登录 | ☐ |
| 2 | 员工工作台可正常访问 | 员工可登录 | ☐ |
| 3 | 团队隔离正常 | 不同团队数据互不可见 | ☐ |
| 4 | AI 对话正常 | 至少 1 个模型可正常回复 | ☐ |
| 5 | 知识库正常 | 上传文档 + 问答正确 | ☐ |
| 6 | SSO 正常（如有） | 企业账号可直接登录 | ☐ |
| 7 | 用量统计正常 | 控制台可看到使用数据 | ☐ |
| 8 | 审计日志正常（Pro+） | 操作记录可查 | ☐ |

> 全部通过 → 签署《验收确认书》 → 交付完成
> 有未通过项 → 记录问题 → 24 小时内修复 → 复验

### Phase 7：上线与回访

**D11 正式上线：**
- [ ] 客户内部公告（建议客户 IT 发全员通知）
- [ ] CRM 状态改为「已上线」
- [ ] 启动计费周期

**D30 首月回访（15 分钟，远程）：**

| 话题 | 目的 |
|------|------|
| 使用数据回顾 | 多少人用了、用了多少、哪个团队最活跃 |
| 满意度 | 有什么问题、哪里不好用 |
| 增购机会 | 是否需要更多节点、更多团队、更多功能 |
| 转介绍 | "您身边有没有朋友也有类似需求？" |

## 四、交付时间标准

| 部署方式 | 总交付周期 | 部署耗时 | 配置耗时 | 培训耗时 |
|---------|:---------:|:-------:|:-------:|:-------:|
| **SaaS** | **3 天** | 30 分钟 | 半天 | 1.5 小时 |
| **私有云** | **5-7 天** | 2 小时 | 1 天 | 1.5 小时 |
| **本地部署** | **1-2 周** | 半天 | 1-2 天 | 1.5 小时 |
| **白牌** | **3 周** | 半天 | 3-5 天 | 1.5 小时 |

## 五、异常处理

| 异常 | 处理方式 | 升级条件 |
|------|---------|---------|
| 客户服务器不达标 | 提供最低配置要求，协助客户升级 | 48 小时未解决 → 升级平台 |
| 网络不通（防火墙/代理） | 提供端口清单，协助 IT 开放 | 客户 IT 无法处理 → 远程协助 |
| SSO 对接失败 | 排查日志，联系客户 IT | 2 天未解决 → 升级平台技术 |
| 模型 API 不可用 | 切换备用模型，排查 API Key | 影响上线 → 升级平台 |
| 客户需求变更 | 评估影响，调整排期，必要时补签变更单 | 超出合同范围 → 商务协商 |
| 客户不配合（拖延提供信息） | 销售跟进催促，每 2 天提醒 | 超 7 天无响应 → 暂停交付 |
