## 〇、虫后的战略意图

```
核心问题：合伙人只拿佣金不投入，退出零成本，不关心平台整体。

解法：让合伙人买期权（星钻），投多少决定佣金率多高。
  不投 = 10% 基础佣金（能干活，但赚得少）
  投满 = 城市最高 30% / 团队最高 20%（全力赚，全力绑定）

  每一轮公式相同：投多少 → 对应多少佣金率
  唯一区别：后面的轮次星钻更贵，达到同样佣金率要花更多钱
  → 早投 = 便宜拿满佣金 + 便宜拿更多星钻 = 双重 FOMO
```

## 一、合伙人期权池

**本设计只涉及合伙人期权，没有外部投资人。**

```
┌──────────────────────────────────────────────────┐
│              合伙人期权池（星钻）                     │
│              总量 1亿份，固定不增发                   │
│              合伙人配额：5000万份（5轮 × 1000万份）   │
├──────────────────────────────────────────────────┤
│ 参与者：城市合伙人 / 团队合伙人                      │
│ 目的：佣金率提升 + 期权池分红 + 星钻增值             │
│ 规则：投多少 → 佣金率多少（10% → 30%/20%）          │
│ 限额：按身份（城市/团队）和轮次独立设定               │
│ 分红：月度期权池入账 × (个人星钻 / 已发行期权星钻)   │
│ 每轮配额：1000万份                                  │
└──────────────────────────────────────────────────┘

星钻总量分配：
  合伙人期权池：5000万份（5轮 × 1000万份，用于合伙人购买）
  平台预留：    3000万份（未来战略用途，暂不流通）
  股权预留池：  2000万份（团队合伙人股权期权 vesting，不参与期权池分红）
  ─────────────────────
  合计           1亿份

三方关系：
  合伙人 ←→ 平台 ←→ 期权池
  每笔消费利润 = 合伙人佣金 + 期权池注入 + 平台留存
```

## 二、合伙人期权佣金机制 — 核心设计

### 2.1 基础规则

```
不投资 → 佣金率 10%（城市和团队都一样）
投了   → 佣金率按投资额占该轮最高额的比例线性提升

城市合伙人：10% → 最高 30%（浮动区间 20%）
团队合伙人：10% → 最高 20%（浮动区间 10%）
```

### 2.2 佣金率公式

**每一轮公式相同：**

```
城市合伙人佣金率 = 10% + (本轮投资额 / 本轮城市最高额) × 20%
团队合伙人佣金率 = 10% + (本轮投资额 / 本轮团队最高额) × 10%

团队最高额 = 城市最高额 × 2（每轮固定倍率）
```

### 2.3 每轮投资限额与佣金率对照

**城市合伙人：**

| 轮次 | 星钻价格 | 最低投资 | 最高投资 | 轮次配额 | 投最低→佣金率 | 投最高→佣金率 |
|------|:-------:|:------:|:------:|:------:|:----------:|:----------:|
| 孢子期 | ¥1.00 | ¥1万 | ¥5万 | 1000万份 | 14% | **30%** |
| 幼虫期 | ¥5.00 | ¥5万 | ¥25万 | 1000万份 | 14% | **30%** |
| 虫兵期 | ¥25.00 | ¥10万 | ¥100万 | 1000万份 | 12% | **30%** |
| 领主期 | ¥125.00 | ¥50万 | ¥500万 | 1000万份 | 12% | **30%** |
| 虫后期 | ¥625.00 | ¥100万 | ¥2000万 | 1000万份 | 11% | **30%** |

**团队合伙人（最高额 = 城市 × 2，共享同一轮次配额）：**

| 轮次 | 星钻价格 | 最低投资 | 最高投资 | 轮次配额 | 投最低→佣金率 | 投最高→佣金率 |
|------|:-------:|:------:|:------:|:------:|:----------:|:----------:|
| 孢子期 | ¥1.00 | ¥2万 | ¥10万 | 1000万份 | 12% | **20%** |
| 幼虫期 | ¥5.00 | ¥10万 | ¥50万 | 1000万份 | 12% | **20%** |
| 虫兵期 | ¥25.00 | ¥20万 | ¥200万 | 1000万份 | 11% | **20%** |
| 领主期 | ¥125.00 | ¥100万 | ¥1000万 | 1000万份 | 11% | **20%** |
| 虫后期 | ¥625.00 | ¥200万 | ¥4000万 | 1000万份 | 10.5% | **20%** |

> **每轮 1000万份配额**，城市和团队合伙人共享。5 轮合计 5000万份，占总量 1亿的 50%。
> 每轮最大募资：孢子 ¥1000万 / 幼虫 ¥5000万 / 虫兵 ¥2.5亿 / 领主 ¥12.5亿 / 虫后 ¥62.5亿
> **配额售罄规则：** 某轮 1000万份卖完后，该轮关闭，合伙人只能在下一轮投资。先到先得。

### 2.4 关键洞察：每轮满额佣金率相同，但成本不同

```
要拿到城市 30% 满额佣金：
  孢子期投满 → 花 ¥5万
  幼虫期投满 → 花 ¥25万     （贵 5 倍）
  虫兵期投满 → 花 ¥100万    （贵 20 倍）
  领主期投满 → 花 ¥500万    （贵 100 倍）
  虫后期投满 → 花 ¥2000万   （贵 400 倍）

同时，早期投的人还拿到更多星钻份额（更便宜的星钻价格）：
  孢子期 ¥5万 → 5万份星钻（占比高 → 分红多）
  虫后期 ¥2000万 → 3.2万份星钻（占比低 → 分红少）

结论：早投 = 便宜拿满佣金 + 便宜拿更多分红份额 = 双重 FOMO
```

### 2.5 佣金率计算示例

```
例1：城市合伙人在孢子期投 ¥3万（最高 ¥5万）
  佣金率 = 10% + (3/5) × 20% = 10% + 12% = 22%
  获得星钻 = ¥3万 / ¥1.00 = 3万份

例2：城市合伙人在幼虫期投 ¥3万（最低 ¥5万）
  → 低于最低投资额，不能投。必须至少投 ¥5万。
  如果投 ¥5万：佣金率 = 10% + (5/25) × 20% = 14%
  获得星钻 = ¥5万 / ¥5.00 = 1万份（比孢子期同样¥5万少得多）

例3：团队合伙人在虫兵期投 ¥100万（最高 ¥200万）
  佣金率 = 10% + (100/200) × 10% = 10% + 5% = 15%
  获得星钻 = ¥100万 / ¥25.00 = 4万份

例4：团队合伙人在虫兵期投满 ¥200万
  佣金率 = 10% + (200/200) × 10% = 20%（满额）
  获得星钻 = ¥200万 / ¥25.00 = 8万份
```

### 2.6 跨轮投资规则

```
合伙人在多轮投资时，佣金率取最高值。
同一轮可以分多次投资，系统按轮次聚合总额计算佣金率。

例：城市合伙人
  孢子期投 ¥3万 → 佣金率 22%，获 3万份星钻
  幼虫期再投 ¥15万 → 本轮佣金率 = 10% + (15/25)×20% = 22%
  
  生效佣金率 = max(22%, 22%) = 22%
  累计星钻 = 3万 + 3万 = 6万份（分红双倍）

如果幼虫期投满 ¥25万：
  本轮佣金率 = 30%
  生效佣金率 = max(22%, 30%) = 30%
  累计星钻 = 3万 + 5万 = 8万份
```

## 三、利润分配架构 — 三方关系

### 3.1 三方分配

每笔 AI 消费利润，只在三方之间分配：**合伙人 + 期权池 + 平台**。

```
  ┌──────────────────────────────────────────────┐
  │            每笔消费利润 100%                    │
  ├──────────────┬────────────┬──────────────────┤
  │    合伙人     │   期权池    │      平台         │
  │  10%~30%    │   20%     │    剩余部分        │
  │ (按投资决定)  │  (恒定)    │   (至少50%)       │
  └──────────────┴────────────┴──────────────────┘

每个客户归属一个合伙人（城市或团队），不会同时归属两个。
```

### 3.2 场景矩阵

| 场景 | 合伙人佣金 | 期权池 | 平台 | 合计 |
|------|:---------:|:-----:|:---:|:---:|
| 城市合伙人（满投 30%） | 30% | 20% | **50%** | 100% |
| 城市合伙人（半投 20%） | 20% | 20% | **60%** | 100% |
| 城市合伙人（不投 10%） | 10% | 20% | **70%** | 100% |
| 团队合伙人（满投 20%） | 20% | 20% | **60%** | 100% |
| 团队合伙人（半投 15%） | 15% | 20% | **65%** | 100% |
| 团队合伙人（不投 10%） | 10% | 20% | **70%** | 100% |
| 无合伙人归属 | — | 20% | **80%** | 100% |

**铁律：**
- 每个客户只归属**一个**合伙人（城市或团队），不存在两个合伙人分同一笔利润
- 期权池 **永远** 20%，不受任何条件影响
- 合伙人不投资也能干活，佣金率 10%
- 平台 **至少** 50%（城市满投时），**最高** 80%（无合伙人时）
- 没人投资 → 平台拿更多 → 公司有更多资金发展

## 四、城市合伙人年费 vs 星钻投资

### 4.1 当前方案：两套并存

| 机制 | 年费 | 合伙人期权（星钻） |
|------|------|-----------------|
| 性质 | 合作服务费（沉没成本） | 投资（有分红+增值+佣金提升） |
| 决定什么 | 合伙人资格准入 | **佣金率**（10%→30%/20%）+ 分红份额 |
| 是否退还 | 不退（次年签≥3客户可返还） | 按协议到期NAV结算退出 |

**虫后的判断：** 年费和期权投资**解决不同问题**：

- **年费** → 准入门槛，筛选合作诚意
- **期权投资** → 决定佣金率高低 + 绑定长期利益 + 参与期权池分红

### 4.2 长期演进（待讨论）

```
Phase 1（现在）：年费 + 期权投资并存
  年费 → 合伙人准入资格
  期权投资 → 决定佣金率（10%~30%/20%）+ 期权池分红

Phase 2（规模化后）：年费可抵扣期权购买
  认证级年费 ¥9,800 → 可抵扣 ¥9,800 的星钻购买
  区域独家年费 ¥29,800 → 可抵扣 ¥29,800 的星钻购买
  效果：交年费 = 自动获得对应金额的星钻 → 佣金率自动提升

Phase 3（成熟期）：取消年费，纯期权投资门槛
  星钻投资 ≥ 当前轮最低额 → 自动获得合伙人资格
  年费消失，全部转为期权投资
```

> Phase 2 和 Phase 3 暂不实施，先跑通 Phase 1 验证模式。

## 五、合伙人收益模型

### 5.1 城市合伙人收益结构

```
┌─ 收益① 佣金收入（即时，每笔消费）
│    归属客户消费利润 × 佣金率
│    佣金率 = 10%（不投资）~ 30%（投满当前轮）
│
├─ 收益② 期权池分红（月度，按星钻持仓）
│    月利润 × 20% × (个人星钻 / 期权池总星钻)
│    投了期权才有星钻，才有分红
│
└─ 收益③ 星钻增值（长期，NAV驱动）
     买入价 → NAV上涨 → 持仓市值增长
     到期可按NAV退出
```

### 5.2 团队合伙人收益结构

```
┌─ 收益① 佣金收入（即时，每笔消费）
│    归属客户消费利润 × 佣金率
│    佣金率 = 10%（不投资）~ 20%（投满当前轮）
│
├─ 收益② 期权池分红（月度，按期权购买的星钻）
│    月利润 × 20% × (期权购买的星钻 / 期权池总星钻)
│
├─ 收益③ 星钻增值（长期，NAV驱动）
│    期权购买的星钻随NAV上涨
│
└─ 收益④ 股权增值（长期，独立于期权池）
     脑虫 3% / 领主 1% 的股权期权 → 仅享有增值权
     股权星钻 ≠ 期权池星钻，不参与期权池 20% 分红
```

> **股权期权不参与期权池分红。** 股权只享有增值权（NAV上涨受益），
> 期权池 20% 分红只分给通过投资购买的星钻持有人。

### 5.3 收益测算

**案例 A：城市合伙人，孢子期投满 ¥5万（佣金率 30%）**

```
时点：孢子期，星钻价格 ¥1.00/份
投资 ¥5万（本轮最高额）→ 佣金率 = 10% + (5/5)×20% = 30%
买到星钻 = ¥5万 / ¥1.00 = 5万份
已发行期权星钻 1000万份 → 占比 0.5%

假设：
  归属客户 10 家，月均消费利润 ¥2,000/家 = ¥20,000 利润
  平台月总利润 ¥500,000
  期权池月入 ¥100,000（月总利润 × 20%）

月收入：
  佣金     = ¥20,000 × 30%           = ¥6,000
  期权分红 = ¥100,000 × 0.5%         = ¥500
  ──────────────────────────────────────
  合计                                 = ¥6,500/月

年收入约 ¥78,000
额外：星钻市值（若NAV涨到¥5.00） = 5万 × ¥5.00 = ¥25万（5倍回报）
```

**案例 A2：城市合伙人，孢子期只投 ¥1万（最低额，佣金率 14%）**

```
投资 ¥1万 → 佣金率 = 10% + (1/5)×20% = 14%
买到星钻 = ¥1万 / ¥1.00 = 1万份 → 占比 0.1%

月收入：
  佣金     = ¥20,000 × 14%           = ¥2,800
  期权分红 = ¥100,000 × 0.1%         = ¥100
  ──────────────────────────────────────
  合计                                 = ¥2,900/月

对比不投资：
  佣金     = ¥20,000 × 10%           = ¥2,000
  期权分红 = ¥0（没有星钻）
  合计                                 = ¥2,000/月

→ 投 ¥1万 后月收入多 ¥900，一年多 ¥10,800 + 星钻增值
→ 约11个月回本，之后全是额外收益
```

**案例 B：团队合伙人（领主 1% 股权），虫兵期投满 ¥200万（佣金率 20%）**

```
时点：虫兵期，星钻价格 ¥25.00/份
投资 ¥200万（本轮团队最高额）→ 佣金率 = 10% + (200/200)×10% = 20%
买到星钻 = ¥200万 / ¥25.00 = 8万份
已发行期权星钻 2000万份

假设：
  归属客户利润 ¥50,000/月
  平台月总利润 ¥500,000
  期权池月入 ¥100,000（月总利润 × 20%）

月收入：
  佣金       = ¥50,000 × 20%              = ¥10,000
  期权池分红 = ¥100,000 × (8万/2000万)     = ¥400
  ─────────────────────────────────────────
  合计                                      = ¥10,400/月

对比不投资（佣金率 10%）：
  佣金       = ¥50,000 × 10%              = ¥5,000
  期权池分红 = ¥0
  合计                                      = ¥5,000/月

→ 投满后月收入多 ¥5,400，年多 ¥64,800 + 星钻增值
额外：股权增值 1% @IPO ¥100亿 = ¥1亿（独立于期权池）
```

> **关键洞察：** 不投资也能干活（10%佣金），但投了赚更多。
> 城市合伙人孢子期只需 ¥5万就能拿满 30% 佣金，约11月回本。
> 团队合伙人的真正大头是股权增值，期权投资是"加速器"。
> 股权增值和期权池分红是两套独立系统。

### 资金注入期权池的两条路径

```
路径①：消费利润注入（自动，每笔消费的 20%）
  POST /internal/option-pool/deposit
  → PoolBalance ↑ → TotalDeposited ↑ → NAV ↑

路径②：合伙人购买期权星钻（手动，真金白银）
  POST /v1/partner/option/purchase
  → TotalRaised ↑ → 合伙人获得星钻份额 → 佣金率提升
  → NAV ↑

路径①推高 NAV（利润驱动）
路径②推高 NAV（资金驱动）
两条路径互为增强
```

## 七、运行时流程（伪代码）

```
InternalProfitSplit(clawID, cost, margin):

  // 1. 加载全局配置
  cfg = LoadProfitConfig()
  // cfg.BaseCommRate     = 0.10   // 基础佣金率（不投资时）
  // cfg.CityMaxRate      = 0.30   // 城市合伙人最高佣金率
  // cfg.TeamMaxRate      = 0.20   // 团队合伙人最高佣金率
  // cfg.OptionPoolRate   = 0.20   // 期权池恒定比例

  // 2. 找到归属合伙人（每个客户只归属一个合伙人）
  user = NodeBinding[clawID].QueenUserID
  partner, partnerType = FindPartner(user)
  // 先查 CityClient 表 → 城市合伙人
  // 再查 CRMDeal 表 → 团队合伙人
  // 只会命中一个

  // 3. 合伙人佣金（按投资额决定佣金率）
  if partner exists:
    rate = CalcPartnerCommRate(partner, partnerType)
    commAmt = margin × rate
    → INSERT Commission(partner, commAmt, "usage", rate=rate)

  // 4. 期权池注入（20%）—— 永远执行
  poolAmt = margin × cfg.OptionPoolRate  // margin × 0.20
  → UPDATE OptionPool SET pool_balance += poolAmt
  → INSERT PoolDeposit(poolAmt, margin, "token_usage", clawID)

  // 5. 平台留存 = margin - commAmt - poolAmt
  //    最少 50%（城市满投时），最多 80%（无合伙人时）


// ── 佣金率计算函数（含过渡期） ──
CalcPartnerCommRate(partner, type):
  // 过渡期：返回旧佣金率
  if partner.transition_end != nil AND now < partner.transition_end:
    return partner.legacy_comm_rate

  // 正常计算：按投资额决定
  baseRate = 0.10
  if type == "city":
    rateRange = 0.20   // 10% → 30%
  else:  // "team"
    rateRange = 0.10   // 10% → 20%

  bestRate = baseRate

  // 按轮次聚合投资额（同一轮可多次投资，取 SUM）
  roundTotals = GROUP BY round.name, SUM(round.amount)
    FROM partner.option_investments

  for each (roundName, totalAmount) in roundTotals:
    roundMax = getRoundMax(roundName, type)
    // type=="team" 时 roundMax = cityMax × 2
    roundRate = baseRate + (totalAmount / roundMax) × rateRange
    bestRate = max(bestRate, roundRate)

  return clamp(bestRate, baseRate, baseRate + rateRange)
```

## 九、与现有系统的关系

### 9.1 佣金阶梯制度（CommissionTier）— 被替代

**旧制度：** 合伙人按累计业绩分级（铜10%/银15%/金20%/钻石25%），被动递增。

**新制度：** 佣金率由**期权投资额**决定（10%→30%/20%），主动投入。

| 维度 | 旧（CommissionTier） | 新（期权佣金绑定） |
|------|---------------------|-------------------|
| 决定因素 | 累计消费利润（被动） | 期权投资额（主动） |
| 调整方式 | 到达门槛自动升级 | 投多少立即生效 |
| 城市合伙人范围 | 10%~25% | 10%~30% |
| 团队合伙人范围 | 10%~25% | 10%~20% |
| 退出成本 | 无 | 有（星钻锁在池子里） |

> `DefaultCommissionTiers` 在新方案上线后**废弃**，改用 `CalcPartnerCommRate`。

### 9.2 星钻系统

复用已有的 InvestorPool（改名 OptionPool）、FundingRound、PoolDeposit 底层结构。变化：

- `InvestorPool` → `OptionPool`（改名，只服务合伙人）
- PoolDeposit 的 Rate 从 0.10 → 0.20
- 合伙人购买走新的 `PartnerOptionInvestment` 表
- 分红逻辑复用，但只分给期权星钻持有人（不含股权星钻）

## 十、飞轮效应 — 为什么这个设计能赢

```
         ┌───────────────────────────────────────────────┐
         │                                               │
         ▼                                               │
  合伙人投资星钻 ←──── 看到佣金率提升+分红，追加投资 ←──┐   │
         │                                            │   │
         ├→ 佣金率提升（10%→30%）                       │   │
         │    → 每笔消费赚更多 → 更积极拓客              │   │
         │                                            │   │
         ├→ 获得星钻份额                                │   │
         │    → 期权池分红                              │   │
         │                                            │   │
         ▼                                            │   │
  更多客户 → 更多 AI 消费 → 更多利润                     │   │
         │                                            │   │
         ├→ 利润 × 佣金率 → 合伙人赚更多 ─────────────┘   │
         ├→ 利润 × 20% → 期权池 → 分红 ───────────────┘   │
         └→ 利润 × ≥30% → 平台 → 投入推广 → 更多用户 ────┘
```

**双重正反馈：**
1. **佣金率正反馈：** 投资 → 佣金率高 → 每笔赚更多 → 更积极拓客 → 更多利润
2. **分红正反馈：** 投资 → 更多星钻 → 更多分红 → 追加投资

### 与传统模式对比

| 维度 | 传统合伙人 | 期权绑定合伙人 |
|------|----------|--------------|
| 佣金率 | 固定比例 | **投多少决定多少**（10%→30%） |
| 关心范围 | 只关心自己客户 | 关心**全平台利润**（影响分红） |
| 退出成本 | ¥0（走就走） | 投资锁在池子里（走了亏钱） |
| 资金贡献 | ¥0 | 真金白银投入平台 |
| 绑定深度 | 浅（佣金关系） | 深（合伙+投资+股东三重身份） |
| 驱动力 | 线性（一个人签一个客户） | 指数（投资→佣金率高→积极→利润高→分红多→继续投资） |
| FOMO | 无 | **双重FOMO**（早投便宜拿佣金率+便宜拿星钻） |

## 十一、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 合伙人不愿投资 | 佣金率停在10%，参与度低 | ① 10%也能干活，不强制 ② 用案例展示投资后收益差距（¥1万→14%，10月回本） |
| 新合伙人加入时已是后期轮次 | 拿满佣金率成本高 | 早投优势是设计意图，后期可平台补贴星钻折扣 |
| 合伙人误解为"承诺收益" | 法律风险 | 协议明确"按实际利润分配"，前端不显示预期收益率 |
| 团队合伙人觉得20%太低 | 人才流失 | 沟通：10%底线，投满20%+股权增值 >> 旧固定佣金 |
| 监管风险（类金融） | 合规问题 | 控制合伙人<200人 + 不公开募集 + 收益权协议框架 |
| 佣金率计算复杂 | 系统出bug | `CalcPartnerCommRate` 单元测试覆盖所有边界 |
| 过渡期成本 | 旧佣金率高于10%的合伙人短期不受激励 | 过渡期内积极沟通 + 展示早期低价优势促成投资 |

## 十二、现有合伙人过渡方案

**已确认：有过渡期，先预留旧佣金率，之后需补交（投资期权）。**

```
过渡规则（先用后付）：
  上线后，现有合伙人保持当前佣金率（过渡期，如3个月）
  过渡期内：
    ① 佣金率 = 旧佣金率（预留，继续正常干活）
    ② 合伙人可以随时投资期权
    ③ 如果投资后的期权佣金率 ≥ 旧佣金率 → 过渡完成，切换到新制度
    ④ 系统记录过渡期内按旧佣金率多发的差额（= 旧佣金率 - 10%基础）

  过渡期结束时：
    A) 已投资够 → 佣金率 = CalcPartnerCommRate()（≥ 旧佣金率）
       过渡期差额一笔勾销
    B) 未投资够 → 佣金率 = CalcPartnerCommRate()（可能 < 旧佣金率）
       过渡期差额需要补交（从后续佣金中扣回，或一次性投资补齐）

补交方式（二选一）：
  方式1：从后续佣金中逐月扣回差额，直到扣完
  方式2：一次性追加投资期权，达到对应佣金率后免除差额

例：城市合伙人旧佣金率 25%，过渡期 3 个月
  过渡期每月归属利润 ¥20,000
  差额 = (25% - 10%) × ¥20,000 × 3个月 = ¥9,000
  如果过渡期内投满孢子期 ¥5万 → 佣金率 30% ≥ 25% → 差额免除
  如果过渡期结束仍未投资 → ¥9,000 从后续佣金逐月扣回

实现方式：
  合伙人表新增字段：
    legacy_comm_rate  float64   // 旧佣金率（过渡期用）
    transition_end    time.Time // 过渡期截止日期
    transition_debt   int64     // 过渡期累计差额（分）
  CalcPartnerCommRate 判断：
    if now < transition_end:
      return legacy_comm_rate  // 预留旧佣金率
    else:
      return 新计算佣金率      // 按实际投资额算
  佣金发放时：
    if transition_debt > 0 AND 过渡期已结束:
      实际发放 = 本期佣金 - min(本期佣金×30%, transition_debt)
      transition_debt -= 扣回金额
```
